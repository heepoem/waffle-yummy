## 제1장: 경영정보 이해

### 1.1 기업의 부문별 활동 이해

기업 경영은 크게 다섯 가지 핵심 기능 영역으로 구분된다. 경영정보시각화 전문가는 각 부문에서 생성되는 데이터의 특성과 활용 방법을 이해해야 한다.

#### 1.1.1 인적자원관리(HRM)

**정의**: 조직의 인력을 효과적으로 확보, 개발, 유지, 활용하는 일련의 관리 활동

**주요 활동**:
- **채용 및 선발**: 인력 수요 예측, 모집, 선발, 배치
- **교육 및 개발**: 직무교육, 역량 개발, 경력 관리
- **성과 관리**: 인사평가, 목표설정, 피드백
- **보상 관리**: 급여, 인센티브, 복리후생
- **노사 관계**: 근로 조건, 단체 협약

**핵심 용어**:
- **이해관계자(Stakeholder)**: 기업 경영에 직간접적으로 영향을 미치는 주체(종업원, 고객, 주주, 지역사회 등)
- **주주(Shareholder)**: 기업의 지분을 소유한 자
- **MBO (Management by Objectives)**: 조직과 개인의 목표를 연계하여 사전에 설정된 목표를 기반으로 객관적이고 결과지향적으로 성과를 관리하는 방법
- **OKR (Objectives and Key Results)**: 목표와 핵심 결과 지표를 설정하여 진보적으로 성과를 관리하는 접근법
- **BSC (Balanced Scorecard)**: 재무, 고객, 업무 프로세스, 학습과 성장 등 네 가지 관점에서 균형 있게 성과를 관리하는 프레임워크
- **KPI (Key Performance Indicator)**: 목표 실현을 위한 주요 활동과 달성 기준을 구체적으로 설정하여 과학적으로 성과를 측정하는 지표

**임금 및 복리후생**:
- 임금 수준 설정 시 조직의 지불 능력, 경쟁사 현황, 노동자 생활권을 동시에 고려
- 임금 인상: 연공 승격, 역할 확대에 따른 성과급, 전체 기준 상향 승급 등
- **법정 복리후생**: 4대 보험(국민연금, 건강보험, 고용보험, 산재보험), 퇴직금
- **법정 외 복리후생**: 자기개발, 생활문화 증진 제도 등
- **카페테리아 제도**: 구성원이 정해진 금액 내에서 원하는 복리후생 프로그램을 선택하는 제도

**인력 운영 계획 수립 시 분석 사항**:
- 부서별 인력 수요와 노동시장 공급 예측
- 조직의 손익과 인건비 현황
- 조직 구성원의 인사평가 관련 정보
- 단·중·장기 자동화 및 아웃소싱 계획

#### 1.1.2 생산관리

**정의**: 제품이나 서비스를 효율적으로 생산하기 위한 계획, 조직, 통제 활동

**주요 활동**:
- **생산 계획**: 수요 예측, 생산 스케줄링, 자재소요계획(MRP)
- **품질 관리**: 품질 검사, 통계적 품질관리(SQC), 총체적 품질경영(TQM)
- **재고 관리**: 적정 재고 수준 유지, JIT(적시생산), EOQ(경제적 주문량)
- **공정 관리**: 공정 설계, 설비 관리, 자동화

**품질 검사 유형**:
- 생산 전 검사
- 생산 중 검사
- 생산 후 검사
- 고객 인도 전 적합성 검사

> **시험 포인트**: "샘플 데이터를 추출하여 수행하는 검사"에 해당하지 않는 것은 "생산 전 검사"이다. (모의문제 17번)

**수요 변화 형태**:
1. **수평적 수요**: 일정한 평균을 중심으로 상승과 하강을 반복
2. **추세적 수요**: 장기적으로 증가 또는 감소하는 경향
3. **계절적 수요**: 특정 시기에 반복적으로 나타나는 패턴
4. **순환적 수요**: 경기 순환에 따른 장기적 변동

#### 1.1.3 마케팅

**정의**: 시장에서 고객의 니즈를 파악하고, 제품/서비스를 통해 가치를 창출·전달하는 활동

**핵심 마케팅 지표**:

| 지표 | 설명 |
|------|------|
| **CPM (Cost Per Mille)** | 1,000회 노출당 비용 = 총비용 ÷ 노출 수 × 1,000 |
| **CPC (Cost Per Click)** | 클릭당 비용 |
| **CPA (Cost Per Action)** | 액션당 비용 |
| **CPI (Cost Per Install)** | 인스톨당 비용 |
| **ROAS (Return On Ad Spend)** | 광고 투자 대비 수익률 |
| **ROI (Return On Investment)** | 특정 활동에 대한 비용 대비 수익의 비율 |
| **CVR (Conversion Rate)** | 전환율 — 특정 행동을 완료한 비율 |
| **CTR (Click Through Rate)** | 광고/링크를 클릭한 사용자의 비율 |
| **LTV (Life Time Value)** | 고객생애가치 — 고객이 장기적으로 회사에 제공하는 예상 가치(순이익 총합) |
| **CRR (Customer Retention Rate)** | 고객유지율 |
| **NPS (Net Promoter Score)** | 순수고객추천지수 |
| **MAU (Monthly Active Users)** | 월간 활성 사용자 수 |
| **Stickiness (고착도)** | 사용자가 제품/서비스를 얼마나 지속적으로 사용하는지 측정 |

> **시험 포인트**: CVR(전환율)은 "웹사이트에서 특정 행동을 완료한 비율"이지, "광고에 노출된 횟수"가 아니다. (모의문제 13번)

**마이클 포터의 5 Forces 모델** (산업 수익성 5가지 경쟁요인):
1. 기존 경쟁자 간의 경쟁 강도
2. 잠재적 경쟁자의 시장 진입 위협
3. 공급자의 교섭력 (가격 결정력)
4. 구매자의 교섭력
5. 대체재의 위협

> **시험 포인트**: "기존 고객의 이탈 가능성"은 5 Forces에 해당하지 않는다. (모의문제 7번)

#### 1.1.4 재무관리

**정의**: 기업의 자금 조달, 운용, 분배에 관한 의사결정 활동

**주요 재무비율**:

| 분류 | 비율 | 설명 |
|------|------|------|
| **안정성** | 부채비율 | 자기자본 대비 부채의 비율 |
| **유동성** | 유동비율 | 유동자산 ÷ 유동부채 |
| **수익성** | 자기자본이익률(ROE) | 당기순이익 ÷ 자기자본 |
| **활동성** | 이자보상비율 | 영업이익 ÷ 이자비용 |
| **투자** | 주가순자산비율(PBR) | 주가 ÷ 주당 장부가치 |
| **투자** | 주당순이익(EPS) | 당기순이익 ÷ 발행주식 수 |
| **투자** | 주당매출액비율(PSR) | 주가 ÷ 주당매출액 |
| **투자** | 주가현금흐름비율(PCR) | 주가 ÷ 주당현금흐름 |

> **시험 포인트**: "기업의 부채 상환 능력"을 측정하는 비율은 이자보상비율이다. "주가가 장부가의 몇 배"는 주가순자산비율(PBR)이다. (모의문제 3, 4번)

**재고가치 평가 방법**:
1. **선입선출법(FIFO)**: 먼저 입고된 상품이 먼저 판매원가로 인식
2. **후입선출법(LIFO)**: 가장 최근에 입고된 상품이 판매원가로 인식
3. **평균법**: 가중평균 단가로 판매원가 계산
4. **개별법**: 각 상품의 실제 원가를 개별 추적

**옵션(Options)**:
- **콜옵션(Call Option)**: 특정 기간 내에 특정 가격으로 자산을 **매수**할 권리(의무 아님)
- **풋옵션(Put Option)**: 특정 기간 내에 특정 가격으로 자산을 **매도**할 권리(의무 아님)

#### 1.1.5 회계

**정의**: 기업의 경제적 거래를 기록, 분류, 요약하여 정보이용자에게 유용한 정보를 제공하는 활동

**회계의 기본 원칙**:
- **발생주의 원칙**: 현금 수수 여부와 관계없이 거래가 발생한 시점에 인식
- **수익비용대응 원칙**: 수익과 비용을 발생한 기간에 정당하게 배분
- **신뢰성 원칙**: 정보가 검증 가능하고 편향되지 않아야 함
- **중요성 원칙**: 의사결정에 영향을 미칠 정도의 항목을 중시

**핵심 용어**:
- **순이익**: 수익에서 비용을 차감한 후 남는 이익
- **매출**: 제품/서비스 판매로 얻은 총금액

## 제2장: 기업 내부정보 파악

### 2.1 회계·재무·인적자원 기본정보

#### 2.1.1 회계정보 관련 용어

| 용어 | 설명 |
|------|------|
| 재무제표 | 기업의 재무상태와 경영성과를 나타내는 보고서 |
| 대차대조표(재무상태표) | 특정 시점의 자산, 부채, 자본 상태 |
| 손익계산서 | 일정 기간의 수익과 비용 |
| 현금흐름표 | 현금의 유입과 유출 |
| 자본변동표 | 자본의 변동 내역 |
| 매출원가 | 판매된 상품/서비스의 직접 원가 |
| 영업이익 | 매출에서 매출원가와 판관비를 뺀 이익 |
| 당기순이익 | 해당 기간의 최종 순이익 |

#### 2.1.2 재무정보 관련 용어

| 용어 | 설명 |
|------|------|
| 자산 | 기업이 소유하는 경제적 자원 |
| 부채 | 타인에 대한 경제적 의무 |
| 자본(자기자본) | 자산에서 부채를 뺀 순자산 |
| 유동자산/유동부채 | 1년 이내에 현금화/상환 가능한 자산/부채 |

## 제4장: 데이터 이해 및 해석

### 4.1 데이터 개념

#### 4.1.1 데이터의 개념

- **데이터(Data)**: 현실 세계에 존재하는 가공되지 않은 사실(fact) — 숫자, 문자, 기호 등의 원시 값
- **정보(Information)**: 데이터를 처리(가공, 분석)하여 의미를 부여한 결과
- **지식(Knowledge)**: 정보를 통해 얻어진 체계화된 이해와 판단

> **시험 포인트**: "데이터는 적절한 의사결정의 수단이 될 수 있다"는 틀린 설명이다. ← 의사결정의 수단은 데이터가 아닌 "정보"이다. "정보란 데이터를 처리해서 얻을 수 있는 결과이다"가 올바른 설명이다. (모의문제 21번)

#### 4.1.2 데이터의 종류

**구조에 따른 분류**:

| 분류 | 설명 | 예시 |
|------|------|------|
| **정형 데이터** | 미리 정의된 구조(스키마)를 가진 데이터, 테이블의 모든 행에 동일한 열 집합 존재 | RDBMS 테이블, 스프레드시트 |
| **반정형 데이터** | 완전한 구조는 아니지만 일부 구조를 가진 데이터 | XML, HTML, JSON |
| **비정형 데이터** | 정해진 구조가 없는 데이터, 분석이 상대적으로 어려움 | 텍스트, 이미지, 동영상, 소셜미디어 |

> **시험 포인트**: "정형 데이터는 주로 XML, HTML, JSON 등의 파일 형태로 저장된다"는 틀린 설명이다. XML, HTML, JSON은 **반정형 데이터**이다. (모의문제 22번)

**측정 수준에 따른 분류**:

| 분류 | 설명 | 예시 |
|------|------|------|
| **범주형 - 명목형** | 분류만 가능, 순서 없음 | 성별, 상품 종류, 거주 지역 |
| **범주형 - 순서형** | 분류 + 순서 존재 | 회원등급, 학력, 만족도(상/중/하) |
| **수치형 - 이산형** | 셀 수 있는 정수값 | 교통사고 발생 횟수, 직원 수 |
| **수치형 - 연속형** | 연속적인 실수값 | 키, 체중, 온도, 매출액 |

> **시험 포인트**: "교통사고 발생 횟수"는 수치형의 이산형 데이터이다. "상품의 종류", "회원등급", "거주 지역"은 범주형이다. (모의문제 23번)

#### 4.1.3 데이터의 종류별 유의사항 및 특성

- **정형 데이터**: 관계형 DB에 저장, SQL로 처리, ACID 트랜잭션 보장
- **비정형 데이터**: NoSQL(특정 스키마가 없는 DB) 활용, Hadoop/Spark 등 빅데이터 플랫폼으로 처리
- **반정형 데이터**: 태그나 키 구조를 통해 일부 구조 제공, Parser로 처리

#### 4.1.4 데이터 파일 형식

| 형식 | 설명 |
|------|------|
| CSV | 쉼표로 구분된 값, 텍스트 기반 |
| TSV | 탭으로 구분된 값 |
| JSON | JavaScript Object Notation, 키-값 쌍 |
| XML | eXtensible Markup Language, 태그 기반 |
| Excel (.xlsx) | Microsoft 스프레드시트 형식 |
| Parquet | 열 기반 바이너리 형식, 빅데이터에 효율적 |

### 4.2 데이터 해석

#### 4.2.1 데이터 해석 관점

데이터를 해석할 때는 다양한 관점에서 접근해야 한다:
- **기술적(Descriptive) 관점**: 데이터가 무엇을 보여주는가?
- **진단적(Diagnostic) 관점**: 왜 이런 결과가 나왔는가?
- **예측적(Predictive) 관점**: 앞으로 어떻게 될 것인가?
- **처방적(Prescriptive) 관점**: 어떤 행동을 취해야 하는가?

#### 4.2.2 데이터 기초통계량

**대표값(중심 경향 측도)**:
- **평균(Mean)**: 모든 값의 합 ÷ N (NULL/결측치는 제외하고 계산)
- **중앙값(Median)**: 데이터를 크기순으로 정렬했을 때 가운데 값
- **최빈값(Mode)**: 가장 자주 나타나는 값

**산포도(변동성 측도)**:
- **범위(Range)**: 최대값 − 최소값
- **분산(Variance)**: 편차 제곱의 평균
- **표준편차(Standard Deviation)**: 분산의 제곱근
- **사분위수(Quartile)**: Q1(25%), Q2(50%=중앙값), Q3(75%)
- **IQR(사분위범위)**: Q3 − Q1

> **시험 포인트**: 데이터 `10, 20, NULL, 30, NULL`에서:
> - **평균**: (10+20+30) ÷ 3 = 20 ✓ (NULL 제외)
> - **데이터의 수**: 유효 데이터 3개 (NULL 포함하면 5개)
> - **중앙값**: 20 (유효 데이터 10, 20, 30 기준)
> - **최빈값**: 없음(모두 1회 출현) 또는 NULL(2회 출현)
> 
> (모의문제 24번, 정답: ① 평균: 20)

#### 4.2.3 확률과 확률분포

**기본 개념**:
- **확률**: 특정 사건이 발생할 가능성 (0 ≤ P ≤ 1)
- **확률분포**: 확률변수가 취할 수 있는 값에 대한 확률 할당

**이산확률분포**:
| 분포 | 설명 |
|------|------|
| 이항분포 | n번의 베르누이 시행에서 성공 횟수의 분포 |
| 포아송분포 | 단위 시간 또는 공간에서 사건 발생 횟수의 분포 |

**연속확률분포**:
| 분포 | 설명 |
|------|------|
| 균등분포 | 모든 구간에서 동일한 확률 |
| 정규분포 | 종 모양 대칭, 평균과 표준편차로 결정 |
| 지수분포 | 사건 사이의 시간 간격 분포 |
| t분포 | 소표본에서 정규분포의 대안 |

> **시험 포인트**: 이항분포는 **이산**확률분포이다. "정규분포, 이항분포"는 연속확률분포의 연결로 적절하지 않다. (모의문제 25번)

**데이터 마이닝 기법**:
| 기법 | 설명 |
|------|------|
| **분류분석(Classification)** | 미리 정의된 카테고리로 데이터를 분류 |
| **군집분석(Clustering)** | 유사도를 측정하여 유사도가 높은 데이터를 그룹화 |
| **연관분석(Association)** | 항목 간의 연관 규칙 발견 (장바구니 분석) |
| **회귀분석(Regression)** | 변수 간의 관계를 수학적으로 모델링 |

> **시험 포인트**: "유사도를 측정하여 유사도가 높은 데이터를 그룹화"하는 기법은 **군집분석**이다. (모의문제 26번)

## 제5장: 데이터 파일 시스템

### 5.1 데이터파일시스템의 개념 및 종류

#### 5.1.1 자료의 계층구조

파일시스템의 자료 계층구조는 3가지 주요 계층으로 구성된다:

```
블록(Block) → 파일(File) → 디렉토리(Directory)
```

- **블록(Block)**: 파일시스템의 가장 낮은 계층, 데이터 저장의 최소 단위
- **파일(File)**: 관련 데이터의 논리적 집합, 고유한 식별자(파일명, 경로)를 가짐
- **디렉토리(Directory)**: 파일을 조직화하는 구조

> **시험 포인트**: "자료의 계층구조는 블록, 파일, 데이터 3가지"에서 "데이터"가 아닌 "디렉토리"가 올바르다. (모의문제 28번)

#### 5.1.2 데이터파일시스템의 개념

- 컴퓨터에서 데이터를 체계적으로 저장하고 관리하는 체계
- 운영체제가 파일을 디스크에 읽고 쓸 수 있도록 지원
- 파일 이름, 경로, 크기, 생성일, 수정일 등 메타데이터 관리

#### 5.1.3 데이터파일시스템의 종류 및 특징

| 파일시스템 | 특징 |
|-----------|------|
| FAT32 | 단순, 호환성 높음, 4GB 파일 크기 제한 |
| NTFS | Windows 표준, 보안·압축·암호화 지원 |
| ext4 | Linux 표준, 대용량 지원, 저널링 |
| APFS | Apple 기기용, 암호화·스냅샷 지원 |
| HFS+ | 기존 Mac 파일시스템 |

### 5.2 데이터베이스 이해

#### 5.2.1 데이터베이스 구성요소

| 구성요소 | 설명 |
|----------|------|
| **메타데이터** | 데이터에 대한 데이터, 데이터의 특성·구조·의미 설명, 보안 관리에도 사용 |
| **저장 데이터 관리자** | 실제 데이터를 물리적으로 저장·관리 |
| **질의처리기** | 사용자의 질의(쿼리)를 처리 |
| **트랜잭션 관리자** | 데이터 일관성과 무결성을 보장 |

> **시험 포인트**: "데이터에 대한 데이터로, 데이터 특성/구조/의미를 설명하는 정보"는 **메타데이터**이다. (모의문제 30번)

#### 5.2.2 데이터베이스 구조

**3단계 구조(스키마)**:
1. **외부 스키마(External Schema)**: 개별 사용자 관점의 논리적 구조
2. **개념 스키마(Conceptual Schema)**: 전체적인 논리적 구조
3. **내부 스키마(Internal Schema)**: 물리적 저장 구조

> **시험 포인트**: "내용 스키마"는 3단계 구조에 해당하지 않는다. (모의문제 32번)

**데이터베이스의 기본 용어**:

| 용어 | 설명 |
|------|------|
| **엔터티(Entity)** | 관리 대상(테이블) |
| **속성(Attribute)** | 테이블의 열(컬럼), 고유한 이름과 데이터 유형을 정의 |
| **레코드(Record)** | 테이블의 행(Row), 하나의 데이터 항목 |
| **릴레이션(Relation)** | 관계형 DB에서의 테이블 자체 |

> **시험 포인트**: "테이블의 열, 특정 데이터 유형에 대한 정보를 기술, 고유한 이름을 가지며 데이터 유형을 정의"하는 것은 **속성(Attribute)**이다. (모의문제 31번)

**중앙집중식 DB vs 분산 DB**:
| 분산 데이터베이스의 장점 |
|--------------------------|
| 시스템 성능 향상 |
| 분산제어 가능 |
| 시스템 확장성 증가 |

> **시험 포인트**: "데이터베이스 설계가 쉽다"는 분산 DB의 장점이 아니라 중앙집중식 DB의 특징이다. (모의문제 27번)

#### 5.2.3 키(Key)의 개념

| 키 종류 | 설명 |
|---------|------|
| **슈퍼키(Super Key)** | 유일성을 만족하는 속성의 집합 |
| **후보키(Candidate Key)** | 유일성 + 최소성을 만족 |
| **기본키(Primary Key)** | 후보키 중 선택된 주 식별자, 중복 불가, NULL 불가 |
| **대체키(Alternate Key)** | 기본키로 선택되지 않은 후보키 |
| **외래키(Foreign Key)** | 다른 테이블의 기본키를 참조 |

> **시험 포인트**: "각 레코드를 고유하게 식별하기 위해 선택된 키, 후보키 중에서 선택, 중복 없음, NULL 불가"는 **기본키(Primary Key)**이다. (모의문제 33번)

#### 5.2.4 변수의 개념

| 변수 유형 | 설명 |
|-----------|------|
| 독립변수 | 다른 변수에 영향을 미치는 원인 변수 |
| 종속변수 | 독립변수에 의해 영향을 받는 결과 변수 |
| 더미변수 | 범주형 데이터를 0/1로 변환한 변수 |
| 매개변수 | 독립변수와 종속변수 사이를 매개하는 변수 |
| 조절변수 | 독립→종속 관계의 강도를 변화시키는 변수 |

## 제6장: 데이터 활용

### 6.1 데이터 가공 방법

#### 6.1.1 데이터 오류와 결측치

- **결측치(Missing Value, NULL)**: 데이터가 비어있거나 누락된 값
- **이상치(Outlier)**: 정상 범위를 벗어난 극단값
- **오류 데이터**: 잘못 입력되거나 형식이 맞지 않는 값

**결측치 처리 방법**:
1. 행 삭제 (리스트와이즈 삭제)
2. 대체 (평균, 중앙값, 최빈값 등으로 대체)
3. 보간법 (전후 데이터를 기반으로 추정)
4. 그대로 유지 (분석 알고리즘이 처리)

#### 6.1.2 데이터 정제

- 중복 데이터 제거
- 이상치 처리 (제거, 치환, 변환)
- 형식 통일 (날짜, 통화, 단위 등)
- 데이터 유효성 검증

#### 6.1.3 데이터 변환

- **스케일링**: 값의 범위를 조정 (정규화, 표준화)
- **인코딩**: 범주형→수치형 변환 (원핫인코딩, 레이블인코딩)
- **집계**: 합계, 평균, 카운트 등 요약
- **파생변수 생성**: 기존 변수를 조합하여 새 변수 생성

#### 6.1.4 데이터 분리

- 학습/검증/테스트 데이터 분리
- 필드(열) 분할
- 조건에 따른 데이터 분리

#### 6.1.5 데이터 결합

- **INNER JOIN**: 양쪽 테이블에 모두 존재하는 데이터만 결합
- **LEFT JOIN**: 왼쪽 테이블 기준 결합
- **RIGHT JOIN**: 오른쪽 테이블 기준 결합
- **FULL OUTER JOIN**: 양쪽 모든 데이터 결합
- **UNION**: 행 방향 결합 (세로로 합치기)

> **시험 포인트**: 데이터를 병합하는 명령어는 **INNER JOIN**이다. SELECT, GROUP BY, ORDER BY는 병합이 아니다. (모의문제 34번)

### 6.2 데이터 관리

#### 6.2.1 데이터 수집 및 전환

- **웹 스크래핑**: 웹사이트에서 데이터를 추출하는 과정
- **API 호출**: REST API 등을 통한 데이터 수집
- **ETL(Extract, Transform, Load)**: 데이터를 추출, 변환, 적재하는 프로세스
- **ELT(Extract, Load, Transform)**: 먼저 적재 후 변환하는 방식

> **시험 포인트**: 웹 스크래핑은 "웹사이트에서 데이터를 추출하는 과정"이다. 보안 강화, 트래픽 생성, 디자인 개선이 아니다. (모의문제 36번)

#### 6.2.2 데이터 적재 및 저장

- **데이터 웨어하우스(DW)**: 의사결정 지원을 위한 통합 데이터 저장소
- **데이터 레이크(Data Lake)**: 원시 데이터를 형식에 구애받지 않고 저장
- **데이터 마트(Data Mart)**: 특정 부서/주제 중심의 소규모 DW

#### 6.2.3 데이터 보안 및 개인정보보호

**데이터 보안 방식**:
| 방식 | 설명 |
|------|------|
| 접근 제어 | 역할에 따라 데이터 사용 권한 할당 |
| 암호화 | 전송 중/저장 시 데이터 암호화 |
| 감사 추적 | 데이터 접근 및 변경 이력 추적 |
| 백업/복구 | 정기적인 데이터 백업과 복구 절차 |

> **시험 포인트**: "데이터 접근을 제어하는 방식"은 "역할에 따라 데이터 사용 권한 할당"이다. (모의문제 35번)

**데이터 무결성 검증**:
- 데이터의 **정확성**, **완전성**, **일관성**을 보장하기 위해 실시

> **시험 포인트**: 데이터 무결성 검증은 "데이터의 정확성, 완전성, 일관성을 보장"하는 것이다. 압축, 암호화, 변환은 무결성 검증이 아니다. (모의문제 38번)

**DBMS 등장 배경**:
- 스키마 정의 및 제약 조건 설정으로 데이터 일관성/무결성 유지
- 동시 접근 제어를 위한 트랜잭션 개념 도입
- 테이블/컬렉션 구조를 사용하여 중복 데이터 최소화

> **시험 포인트**: "제한된 데이터 검색 기능을 개선하고자 DBMS 자료의 계층구조를 구성한다"는 올바르지 않다. 계층구조는 파일시스템의 개념이다. (모의문제 29번)

**NoSQL 데이터베이스**:
- 유연한 스키마 설계를 제공
- 비정형 또는 반정형 데이터 처리에 적합
- 미리 정의된 스키마가 **불필요** (미리 정의된 스키마를 제공한다는 것은 오류)
- SQL이 아닌 자체 쿼리 언어 사용

> **시험 포인트**: NoSQL의 특징은 "유연한 스키마 설계를 제공하고 비정형 또는 반정형 데이터를 처리"하는 것이다. (모의문제 37번)

### 6.3 비즈니스 인텔리전스(BI)

#### 6.3.1 비즈니스 인텔리전스의 개념

**정의**: 기업 내외부의 데이터를 수집·분석하여 의사결정에 필요한 통찰(Insight)을 제공하는 전략적 접근법

**구성요소**:
- 데이터 수집 및 통합
- 데이터 분석 및 마이닝
- 보고(Reporting) 및 시각화
- 과거 성과 분석 및 미래 예측

#### 6.3.2 비즈니스 인텔리전스와 데이터 기반 의사결정

- **데이터 기반 의사결정(Data-Driven Decision Making)**: 직감이 아닌 데이터와 분석에 기반한 의사결정
- **실행 가능한 통찰(Actionable Insight)**: 데이터 분석으로부터 도출된 실질적 행동 지침

#### 6.3.3 비즈니스 인텔리전스의 활용

**BI 활용 목적**:
- 데이터 기반 의사결정의 지원과 실행 가능한 통찰 제공 ✓
- 마케팅 전략 개발 및 실행 ✓
- 일상적인 비즈니스 프로세스의 자동화 ✓

> **시험 포인트**: "데이터 보안 및 개인정보 보호 조치 강화"는 BI의 직접적 목적이 아니다. (모의문제 39번)

**BI 구현의 이점**:
- **의사결정 능력 및 전략적 통찰 향상** ✓
- 데이터 복잡성/혼란 증가 ✗
- 데이터 분석의 필요성 감소 ✗ (오히려 증가)
- 제한된 접근 ✗ (접근성 향상이 이점)

> **시험 포인트**: BI 구현의 이점은 "의사결정 능력 및 전략적 통찰 향상"이다. (모의문제 40번)

## 제7장: 시각화 디자인 기본원리 이해

### 7.1 디자인의 기본 원리

시각화 디자인은 정보를 명확하고 효과적으로 전달하기 위한 기본 원리에 기초한다.

| 원리 | 설명 |
|------|------|
| **리듬(Rhythm)** | 두 개 이상의 요소가 반복되어 일정 패턴을 형성하는 것 |
| **강조(Emphasis)** | 특정 요소를 돋보이게 하여 시선을 집중시킴 |
| **대비(Contrast)** | 상반되는 요소의 차이를 통해 시각적 흥미 유발 |
| **대칭(Symmetry)** | 중심축을 기준으로 좌우/상하가 균등한 배치 |
| **변화(Variety)** | 다양한 요소를 활용하여 단조로움을 방지 |
| **통일(Unity)** | 전체적으로 하나의 일관된 느낌을 주는 것 |
| **조화(Harmony)** | 서로 다른 요소들이 어울려 유기적인 관계를 형성 |
| **균형(Balance)** | 시각적 무게감이 균등하게 분배된 상태 |
| **형태(Form)** | 시각적 요소의 외형적 모양 |
| **공간(Space)** | 요소들 사이의 빈 영역, 여백 |
| **규모(Scale)** | 디자인 요소의 절대적 크기 |
| **비례(Proportion)** | 요소들 간의 상대적인 크기와 배치의 조합 |

**색상의 3속성**:
- **색상(Hue)**: 빨강, 파랑 등 색의 종류
- **명도(Value/Brightness)**: 색상의 밝기 정도
- **채도(Saturation)**: 색의 순수도 (0% = 가장 탁한 색, 100% = 순수한 색)

> **시험 포인트**:
> - "균형은 디자인 요소들 간의 크기와 비율을 나타낸다"는 틀리다 ← 이것은 **비례**의 설명이다. 균형은 시각적 무게감의 균등 분배이다. (모의문제 41번)
> - "두 개 이상의 요소가 반복되어 일정 패턴이 형성"되는 것은 **리듬**이다. (모의문제 42번)

### 7.2 인포그래픽 디자인

#### 7.2.1 인포그래픽 유형과 원리

**인포그래픽(Infographic)**: 정보(Information) + 그래픽(Graphic) — 복잡한 정보를 시각적으로 명확하게 전달하는 디자인

**주요 유형**:

| 유형 | 설명 |
|------|------|
| **통계 인포그래픽** | 수치 데이터를 차트·그래프로 표현 |
| **타임라인/역사적 인포그래픽** | 시간 순서에 따른 변화나 역사적 이벤트를 시각화 |
| **프로세스/플로우차트** | 과정이나 절차를 단계별로 시각화 |
| **비교 및 대조 인포그래픽** | 두 가지 이상의 대상을 비교 |
| **지도/지리적 인포그래픽** | 지리적 정보를 시각화 |
| **계층적 인포그래픽** | 정보의 계층 구조를 표현 |
| **목록형 인포그래픽** | 정보를 항목별로 나열 |

> **시험 포인트**: "비교 및 대조 인포그래픽"의 설명에서 "아이콘, 그림, 이미지를 활용하여 정보를 시각적으로 전달한다"는 비교·대조의 핵심 설명이 아니다. 비교·대조는 두 대상의 차이와 공통점을 대비하는 것이 핵심이다. (모의문제 44번)

**인포그래픽 디자인 원칙**:
- **오컴의 면도날 원칙**: 복잡한 정보를 가장 간결하고 단순하게 전달. 핵심 메시지 강조, 단순한 시각화, 명확한 구조화, 최소한의 텍스트
- **브랜드 아이덴티티**: 기업/조직의 정체성을 반영
- **정보의 일관성**: 데이터의 정확성과 표현의 일관성 유지
- **타깃 오디언스**: 대상 독자에 맞는 정보 수준과 표현 방식

> **시험 포인트**: "더 간결하고 이해하기 쉽게, 논리적 추론에도 적용, 핵심 메시지 강조, 단순한 시각화"에 해당하는 원칙은 **오컴의 면도날**이다. (모의문제 43번)

#### 7.2.2 인포그래픽 디자인 구성요소

| 구성요소 | 설명 |
|----------|------|
| **질감(Texture)** | 표면의 시각적/촉각적 느낌 |
| **제목(Title)** | 인포그래픽의 핵심 메시지를 전달 |
| **서체(Typography)** | 글의 가독성과 분위기를 좌우 |
| **주석(Annotation)** | 차트/그래프에 대한 추가 설명 |
| **격자선(Grid Line)** | 데이터 값 비교를 돕는 기준선 |
| **클립아트(Clip Art)** | 미리 제작된 이미지/아이콘 |
| **두 번째 축(Secondary Axis)** | 이중 축으로 다른 단위의 데이터 표현 |
| **범례(Legend)** | 색상·패턴·기호가 무엇을 의미하는지 설명하는 가이드 |
| **배경(Background)** | 전체적인 디자인 분위기 설정 |

> **시험 포인트**: "그래프에서 사용된 색상, 패턴, 기호와 항목을 설명하는 텍스트 요소, 가독성 향상, 시각적 가이드"는 **범례(Legend)**이다. (모의문제 45번)

## 제8장: 시각화 도구 활용

### 8.1 사무자동화 프로그램을 활용한 시각화

#### 8.1.1 사무자동화 프로그램의 시각화 관련 주요 기능

**Microsoft Excel**:
- **차트 기능**: 막대, 꺽은선, 원형, 분산형 등 다양한 차트 유형
- **조건부 서식**: 데이터 값에 따라 셀의 서식 자동 변경
  - **데이터 막대**: 셀 내에 가로 막대 표시
  - **색 스케일**: 값에 따른 색상 그라데이션
  - **아이콘 세트**: 값의 범위에 따른 아이콘 표시
- **스파크라인**: 셀 하나에 표시되는 작은 차트 (꺽은선, 열, 승패)
- **피벗 테이블**: 데이터를 요약·분석하는 대화형 테이블
- **슬라이서**: 피벗 테이블/차트의 필터링 도구

> **시험 포인트**: 엑셀에서 셀 내에 작은 차트를 표시하는 기능은 **스파크라인**이다. (모의문제 46번)

#### 8.1.2 사무자동화 프로그램 활용 시각화의 장단점

| 장점 | 단점 |
|------|------|
| 접근성이 높음 (대부분의 사용자가 보유) | 대용량 데이터 처리 한계 |
| 학습 곡선이 낮음 | 실시간 데이터 연동 어려움 |
| 빠른 프로토타이핑 가능 | 대화형 대시보드 구현 제한적 |
| 다양한 기본 차트 제공 | 복잡한 시각화 구현 어려움 |

### 8.2 시각화 도구(BI 소프트웨어)의 특징

#### 8.2.1 주요 BI 소프트웨어 비교

| 도구 | 특징 |
|------|------|
| **Power BI** | Microsoft 제품, Office 365 통합, DAX 함수, 데이터 추출/변환/시각화 전 과정 지원 |
| **Tableau** | 직관적 드래그앤드롭, 강력한 시각화, 다양한 데이터 소스 연결 |
| **Qlik Sense** | 연관 데이터 모델, 사용자 친화적 탐색 |
| **Google Looker Studio** (구 Data Studio) | 무료, Google 서비스 통합 |

**시각화 도구의 특징**:
- 동일한 데이터에 대해 다양한 시각화 방법을 빠르게 적용 가능
- 재현 가능성 구현에 강점
- 무작위 요소가 포함된 경우 반복 가능성 구현이 어려울 수 있음

> **시험 포인트**: "Power BI는 데이터 시각화를 위한 전용 도구로 데이터 추출 및 변환 기능은 제공하지 않는다"는 **틀린** 설명이다. Power BI는 Power Query를 통해 데이터 추출 및 변환 기능을 모두 제공한다. (모의문제 47번)

#### 8.2.2 시각화 도구의 장단점

| 장점 | 단점 |
|------|------|
| 대용량 데이터 처리 가능 | 학습 곡선 존재 |
| 대화형(Interactive) 시각화 | 라이선스 비용 |
| 실시간 데이터 연동 | 초기 설정 복잡할 수 있음 |
| 자동 새로고침 | 인터넷 연결 필요(클라우드 버전) |
| 협업 및 공유 기능 | |

### 8.3 시각화 도구(BI 소프트웨어)의 주요 기능

#### 8.3.1 대시보드의 개념 및 특징

**대시보드(Dashboard)**: 핵심 지표와 데이터를 한 화면에서 시각화하여 보여주는 인터페이스

**특징**:
- 여러 시각화 차트를 한 화면에 배치
- **상호작용(Interactive) 및 필터링 기능** 제공
- 실시간 데이터 모니터링 가능
- 드릴다운(Drill-down) 기능으로 상세 분석

> **시험 포인트**: "대시보드는 상호작용 또는 필터링 기능을 제공하지 않는다"는 **틀린** 설명이다. 대시보드의 핵심 기능 중 하나가 바로 상호작용/필터링이다. (모의문제 48번)

#### 8.3.2 시각적 요소의 상호작용

- **필터(Filter)**: 특정 조건에 맞는 데이터만 표시
- **하이라이트(Highlight)**: 선택한 항목을 강조 표시
- **드릴다운(Drill-down)**: 상위 수준에서 하위 수준으로 상세 탐색
- **슬라이서(Slicer)**: 시각적 필터 요소
- **툴팁(Tooltip)**: 마우스 오버 시 상세 정보 표시
- **크로스필터(Cross-filter)**: 하나의 시각화 선택이 다른 시각화에 영향

## 제9장: 시각화 요소 디자인

### 9.1 차트 디자인

시험에서 가장 많은 비중을 차지하는 영역이다. 각 차트 유형의 특징, 적합한 데이터 유형, 장단점을 정확히 이해해야 한다.

#### 9.1.1 막대차트(Bar Chart)

**특징**:
- 범주형 데이터의 값을 비교하는 데 적합
- 수직(Column)과 수평(Bar) 방향 모두 가능
- 데이터 값의 차이를 직관적으로 파악

**종류**:
- **기본 막대차트**: 단일 범주 비교
- **그룹화 막대차트**: 여러 계열 비교
- **누적막대차트**: 전체 대비 각 부분의 구성 비율 표현

#### 9.1.2 꺽은선 차트(Line Chart)

**특징**:
- 시간에 따른 데이터의 추세와 변화를 표현하는 데 최적
- 연속적인 데이터 흐름을 보여줌
- 여러 계열의 추세를 비교하기 용이

#### 9.1.3 원형 차트(Pie Chart)

**특징**:
- 전체 대비 각 항목의 비율(구성비)을 표현
- 항목 수가 적을 때 효과적 (5~7개 이하 권장)
- 정확한 값 비교는 어려움

#### 9.1.4 도넛 차트(Donut Chart)

**특징**:
- 원형 차트의 변형, 중앙이 비어있음
- 중앙 공간에 합계나 제목 등 추가 정보 표시 가능
- 여러 수준의 데이터를 동심원으로 표현 가능

#### 9.1.5 분산형 차트(Scatter Plot)

**특징**:
- 두 변수 간의 관계(상관관계)를 표현
- 데이터 포인트의 분포 패턴 확인
- 이상치(Outlier) 탐지에 유용

**버블차트(Bubble Chart)**: 분산형 차트의 확장
- 세 번째 변수를 버블의 **면적**으로 표현 (지름이 아닌 면적으로 비교)
- 범주형 데이터를 각 범주의 쌍으로 비교 가능
- 원형뿐만 아니라 사각형, 삼각형 형태로도 활용 가능
- 좁은 공간에 대량 데이터 표시에 용이

> **시험 포인트**: "비교하기 쉽고 대량의 데이터를 좁은 공간에 표시하기 용이하다"는 버블차트의 장점이지만 단점이 될 수도 있다. "범주형 데이터 간 차이를 각 범주의 쌍으로 비교하기에 적합하다"는 적절하지 않다 — 이는 분산형 차트의 특성에 더 가깝다. (모의문제 53번)

#### 9.1.6 트리맵 차트(Treemap)

**특징**:
- 계층 구조가 있는 데이터 표현에 적합
- 계층 내 비율을 면적으로 편리하게 표현
- 인접하지 않은 범주형 데이터의 **계층간 비교가 어려움** (인접한 비교는 가능)
- 대상 배치는 BI 도구의 알고리즘에 의해 결정되어 통상적으로 제어가 어려움
- 음수 값 표현이 어려움

> **시험 포인트**: "인접하지 않은 범주형 데이터의 계층간 비교에 용이하다"는 **틀린** 설명이다. 비교가 **어렵다**가 맞다. (모의문제 57번)

#### 9.1.7 영역 차트(Area Chart)

**특징**:
- 꺽은선 차트와 유사하지만 선 아래 영역을 색으로 채움
- 시간에 따른 양적 변화를 시각적으로 강조
- 누적 영역 차트로 전체와 부분의 비율 표현 가능

#### 9.1.8 결합형 차트(Combo Chart)

**특징**:
- 두 가지 종류의 차트를 한 화면에 결합
- 예: 막대차트 + 꺽은선 차트
- 이중 축 활용으로 단위가 다른 데이터 동시 표현
- 서로 다른 관점의 데이터를 비교

#### 9.1.9 박스플롯(Box Plot)

**특징**:
- 데이터의 분포를 다섯 가지 요약 통계로 표현: **최소, Q1(1사분위수), 중위수, Q3(3사분위수), 최대**
- 이상치 탐지가 가능하여 데이터 전처리에 활용
- 데이터의 분포를 잘 보여주며 다른 데이터군과 쉽게 비교 가능

> **시험 포인트**: "신뢰구간을 표시하여 불확실성을 나타낼 수 있다"는 박스플롯의 일반적 설명이 아니다. (모의문제 53번)

#### 9.1.10 시간 전후 관계 표현 차트

**경사차트(Slope Chart)**:
- 정량 데이터의 시간 전후 관계(변화)를 표현하기에 가장 적합
- 두 시점 사이의 데이터 변화를 기울기로 직관적 제시

> **시험 포인트**: "정량 데이터의 시간 전후 관계"를 표현하기 가장 적한 차트는 **경사차트**이다. (모의문제 49번)

#### 9.1.11 기타 차트 유형

| 차트 유형 | 설명 |
|-----------|------|
| **히스토그램** | 연속형 데이터의 빈도 분포를 막대로 표현 |
| **히트맵** | 행렬 형태로 색상 강도로 값의 크기를 표현 |
| **바이올린차트** | 데이터의 분포를 커널 밀도 추정으로 표현 |
| **수평오차막대** | 데이터의 불확실성(오차 범위)을 표현하기에 적합 |
| **밀도분포** | 연속형 데이터의 확률 밀도 표현 |
| **생키차트(Sankey)** | 플로우(흐름)를 너비로 표현 |
| **버터플라이차트** | 두 그룹을 좌우 대칭으로 비교 |
| **스파이더/레이더차트** | 여러 항목을 방사형으로 비교, 항목 간 비율·균형·경향 파악 |
| **덴드로그램** | 계층적 군집 분석 결과를 트리 구조로 표현 |
| **간트차트** | 프로젝트 일정 관리, 작업의 시작/종료 시기 표현 |

> **시험 포인트**:
> - "데이터의 불확실성을 표현하기 가장 적합한" 차트는 **수평오차막대**이다. (모의문제 51번)
> - "비교 항목이 4개 이상일 때 사용, 항목 간 비율·균형·경향을 직관적으로 파악"하는 차트는 **스파이더차트(레이더차트)**이다. 단, "비교 항목이 네 개 이상일 경우에 사용"이라는 제한은 없다 — 3개 이상이면 사용 가능하다. (모의문제 54번)

### 9.2 맵(Map) — 지리 정보 시각화

| 맵 유형 | 설명 |
|---------|------|
| **단계구분도(Choropleth Map)** | 지역을 색상의 진하기로 데이터 값 표현 |
| **카토그램(Cartogram)** | 지역의 면적을 데이터 값에 비례하여 왜곡 |
| **카토그램 히트맵** | 카토그램 + 색상 강도 결합 |
| **밀도맵(Density Map)** | 데이터 포인트의 밀집도를 색상으로 표현 |
| **비례 기호 맵** | 원이나 버블의 크기로 데이터 값 표현 |

> **시험 포인트**: 지역 면적을 왜곡하여 표현하는 차트는 **카토그램**이다. (모의문제 58번)

### 9.3 시각 속성

| 시각 속성 | 적합한 데이터 | 주요 용도 |
|-----------|-------------|----------|
| **위치(Position)** | 정량/범주형 | 가장 정확한 인코딩 |
| **길이(Length)** | 정량형 | 막대 차트 등 |
| **각도(Angle)** | 정량형 | 원형 차트 |
| **면적(Area)** | 정량형 | 버블, 트리맵 |
| **색상(Color Hue)** | **범주형** | 분류, 구분, 강조 |
| **색상 밝기(Brightness)** | 정량형 | 히트맵 |
| **형태(Shape)** | **범주형** | 분류, 구분 |
| **선 유형(Line Type)** | **범주형** | 분류, 구분 |

> **시험 포인트**: 범주형 데이터에 주로 사용되는 시각 속성 중 **위치**는 "분류, 구분 혹은 강조의 목적"보다는 정량적 비교에 더 적합하다. (모의문제 55번)

### 9.4 기타 시각화 차트

**분위수-분위수 차트(QQ Plot)**:
- 두 확률분포를 비교하는 데 사용
- 데이터가 특정 분포(예: 정규분포)를 따르는지 확인

> **시험 포인트**: X축과 Y축에 분위수를 표시한 차트(직선에 가까우면 정규분포)는 **분위수-분위수 차트(QQ도표)**이다. (모의문제 59번)

**역사차트/간트차트**:
- Joseph Priestley의 역사차트: 시간 축 위에 인물의 생애 기간을 막대로 표현
- 이는 현대의 **간트차트**와 가장 유사

> **시험 포인트**: Joseph Priestley의 역사차트는 **간트차트**와 관련이 있다. (모의문제 60번)

### 9.5 테이블 디자인

#### 9.5.1 테이블

- 데이터를 행과 열의 구조로 표현
- 정확한 값을 비교할 때 차트보다 유용
- 조건부 서식으로 시각적 효과 추가 가능

#### 9.5.2 캘린더 차트

- 달력 형태로 데이터를 표현
- 일별/주별 패턴 파악에 유용
- 색상 강도로 값의 크기를 표현 (히트맵 방식)

## 제10장: 경영정보시각화 작업 준비

### 10.1 프로그램 실행하기

#### Power BI Desktop
1. 프로그램 실행
2. 시작 화면에서 "데이터 가져오기" 또는 빈 보고서 선택
3. 인터페이스 구성:
   - **리본 메뉴**: 홈, 삽입, 모델링, 보기 등
   - **시각화 창**: 시각화 유형 선택 및 설정
   - **필드 창**: 데이터 모델의 테이블과 필드
   - **필터 창**: 데이터 필터 설정
   - **캔버스**: 시각화 요소 배치 영역

#### Tableau Desktop
1. 프로그램 실행
2. 시작 페이지에서 데이터 소스 연결
3. 인터페이스 구성:
   - **데이터 창**: 차원(Dimension)과 측정값(Measure)
   - **열/행 선반(Shelf)**: 필드 배치
   - **마크 카드**: 색상, 크기, 레이블, 도구설명 등
   - **필터 선반**: 데이터 필터링
   - **페이지 선반**: 페이지별 시각화

### 10.2 파일 관리하기

#### 데이터 불러오기

**Power BI 지원 데이터 소스**:
- Excel 통합 문서 (.xlsx, .xlsm)
- CSV 파일 (.csv)
- SQL Server, Azure SQL 등 데이터베이스
- SharePoint, Dataverse 등 온라인 서비스
- Web, OData, JSON 등

**Tableau 지원 데이터 소스**:
- Excel, CSV, JSON
- SQL Server, MySQL, PostgreSQL
- Google Sheets, Salesforce
- OData, Web Data Connector

#### 작업 문서 저장
- **Power BI**: .pbix 형식으로 저장
- **Tableau**: .twb(데이터 미포함) 또는 .twbx(데이터 포함) 형식

### 10.3 데이터 가공하기

#### 데이터 결합

**Power BI (Power Query)**:
- **쿼리 병합(Merge)**: JOIN 방식으로 테이블 결합 (Inner, Left Outer, Right Outer, Full Outer 등)
- **쿼리 추가(Append)**: UNION 방식으로 행 방향 결합

**Tableau**:
- **조인(Join)**: Inner, Left, Right, Full Outer Join
- **유니온(Union)**: 행 방향 결합
- **블렌딩(Blending)**: 서로 다른 데이터 소스 연결

#### 필드 분할 및 결합

**Power BI**:
- Column by Example: 예시 기반 열 분할
- 열 분할: 구분 기호, 문자 수 기준
- 열 병합: 여러 열을 하나로 결합

**Tableau**:
- SPLIT() 함수: 필드 분할
- 계산된 필드: 여러 필드를 수식으로 결합

#### 필드 속성 변경

**공통 작업**:
- 필드 이름(명칭) 변경
- 데이터 유형 변경 (텍스트, 숫자, 날짜, 부울 등)
- 형태 변경 (피벗, 언피벗)

### 10.4 데이터 계산하기

#### Power BI — DAX 기본 함수

```
// 합계
Total Sales = SUM(Sales[Amount])

// 평균
Avg Price = AVERAGE(Products[Price])

// 개수
Order Count = COUNT(Orders[OrderID])

// 조건부 계산
High Sales = CALCULATE(SUM(Sales[Amount]), Sales[Amount] > 1000)

// IF 조건
Status = IF(Sales[Amount] > 500, "High", "Low")

// 나눗셈 (안전)
Profit Margin = DIVIDE(Sales[Profit], Sales[Revenue], 0)

// 날짜 계산
Year = YEAR(Sales[OrderDate])

// 누계
Running Total = CALCULATE(
    SUM(Sales[Amount]),
    FILTER(ALL(Calendar), Calendar[Date] <= MAX(Calendar[Date]))
)
```

#### Tableau — 기본 계산식

```
// 합계
SUM([Sales])

// 평균  
AVG([Profit])

// 조건문
IF [Sales] > 500 THEN "High" ELSE "Low" END

// 날짜 부분 추출
DATEPART('year', [Order Date])

// 문자열 결합
[First Name] + " " + [Last Name]

// LOD 표현식 (Level of Detail)
{FIXED [Region] : SUM([Sales])}
```

## 제11장: 경영정보시각화 결과물 레이아웃 구성

### 11.1 레이아웃 구성하기

#### 기본 원리
- **그리드 시스템**: 일정한 격자 기반으로 시각화 요소 배치
- **정보 계층**: 중요도에 따라 시각적 요소의 크기와 위치 결정
- **F패턴/Z패턴**: 사용자의 시선 흐름을 고려한 배치

#### Power BI 레이아웃
1. 캔버스에 시각화 요소 자유롭게 배치
2. 격자에 맞춤(Snap to Grid) 기능 활용
3. 시각화 개체 크기 조정 및 정렬
4. 페이지 크기 설정 (표준, 와이드스크린, 사용자 지정 등)

#### Tableau 레이아웃
1. 대시보드 새로 만들기
2. 크기 설정 (고정, 자동, 범위)
3. 시트를 드래그하여 대시보드에 배치
4. 타일(Tiled) 또는 부동(Floating) 레이아웃 선택

### 11.2 시각화 요소 배치 및 추가 요소 삽입

**삽입 가능한 요소**:
- **도형**: 사각형, 원, 화살표 등으로 영역 구분
- **이미지**: 로고, 아이콘, 배경 이미지
- **텍스트**: 제목, 부제목, 설명 텍스트 상자

### 11.3 대화식(Interactive) 화면 구성하기

#### 필터 구성

**Power BI**:
- **슬라이서(Slicer)**: 사용자가 선택한 필드의 데이터가 전체 시각화에 적용
- **필터 창(Filter Pane)**: 시각적 수준, 페이지 수준, 보고서 수준 필터
- **상호 작용(Interaction)**: 한 시각화 선택 시 다른 시각화 연계 반응

**Tableau**:
- **필터**: 차원/측정값 필터, 컨텍스트 필터
- **하이라이트 액션**: 선택 항목만 강조 표시
- **필터 액션**: 선택 시 다른 시트의 데이터 필터링
- **매개변수(Parameter)**: 사용자 입력 값에 따른 동적 변화

#### 강조 표시
- 사용자가 선택한 항목만 강조(Highlight)되도록 설정
- 비선택 항목은 흐리게(Dim) 처리

#### 내비게이션
- **Power BI**: 단추(Button) 생성으로 다른 페이지나 북마크로 이동
- **Tableau**: 대시보드 액션으로 다른 시트나 URL로 이동
- 웹페이지로 이동하는 단추 생성 가능

### 12.1 차트 구성하기

#### 기본 형태의 차트 구성

**Power BI에서 차트 만들기**:
1. 시각화 창에서 차트 유형 선택

**Tableau에서 차트 만들기**:
1. 데이터 창에서 필드를 열/행 선반에 드래그
2. 마크 카드에서 차트 유형 변경
3. 색상, 크기, 레이블 등 마크 속성 설정

#### 복잡한 형태의 차트 구성

- **결합형 차트**: 두 가지 차트 유형을 한 화면에 표시
- **이중 축 활용**: 서로 다른 단위의 데이터를 하나의 차트에 표현
  - Power BI: 보조 축 추가
  - Tableau: 이중 축(Dual Axis) 설정

#### 차트에 레이블 표현

- 데이터 값을 차트 위에 직접 표시
- 위치, 서체, 크기, 색상 등 커스터마이징
- 단위 표시 (%, 원, 개 등)

### 12.2 테이블 구성하기

**테이블을 응용한 시각적 요소**:
- 행렬(Matrix) / 피벗 테이블
- 조건부 서식을 적용한 테이블 (데이터 막대, 배경색, 아이콘)
- 하이라이트 테이블 / 히트맵

### 12.3 시각화요소 디자인 변경하기

**변경 가능한 디자인 요소**:
- **글꼴**: 서체, 크기, 색상, 굵기, 기울임
- **색상**: 배경색, 데이터 색상, 조건부 색상
- **테두리**: 두께, 색상, 스타일
- **도형**: 구분선, 배경 도형 등

### 12.4 기능 활용하기

#### 빠른 계산(Quick Table Calculation)

**Tableau의 빠른 테이블 계산**:
- 누계(Running Total)
- 차이(Difference)
- 비율 차이(Percent Difference)
- 구성비(Percent of Total)
- 이동평균(Moving Average)
- 순위(Rank)

**Power BI의 빠른 측정(Quick Measure)**:
- 범주별 평균
- 기간 비교
- 누계
- 필터링된 값

#### 필터 적용
- 특정 조건에 맞는 데이터만 나타내도록 필터 설정
- 날짜 범위, 상위/하위 N개, 특정 값 포함/제외

#### 축 설정 변경
- X축/Y축 범위 (최소/최대값) 조정
- 로그 스케일 적용
- 축 역전(Reverse)
- 축 제목 변경

#### 범례 만들기
- 범례 위치 조정 (상단, 하단, 좌측, 우측)
- 범례 항목 이름 변경
- 범례 스타일 설정

#### 분석 기능 활용
- **추세선(Trend Line)**: 데이터의 전반적 경향
- **평균선(Average Line)**: 평균값 표시
- **중앙값선**: 중앙값 표시
- **참조선(Reference Line)**: 특정 기준값 표시
- **예측(Forecast)**: 시계열 데이터 기반 미래 예측

#### 데이터 설명 변경
- 축 제목, 차트 제목, 도구 설명 등의 텍스트 수정
- 사용자 맞춤형 도구 설명(Tooltip) 구성

| 16 | ③ | "운영 요구사항 이하의 제품 획득"은 구매관리 역할이 아님 |
| 17 | ② | 샘플 데이터 추출 검사에 해당하지 않는 것은 "생산 중 검사" |
| 18 | ① | 평균 중심 상승/하강 반복은 **수평적 수요** |
| 19 | ④ | 공급사슬 이동 유형이 아닌 것은 "직원 인사 이동" |
| 20 | ① | 지역자치단체 관련 정보는 **E-지방지표** |

### 제2과목: 데이터 해석 및 활용 (21-40번)

| 번호 | 정답 | 해설 |
|------|------|------|
| 21 | ③ | 정보란 **데이터를 처리해서 얻는 결과** |
| 22 | ② | XML, HTML, JSON은 정형이 아닌 **반정형** 데이터 형태 |
| 23 | ④ | 수치형 이산형 데이터는 **교통사고 발생 횟수** |
| 24 | ① | 10, 20, NULL, 30, NULL의 평균: (10+20+30)/3 = **20** |
| 25 | ④ | 이항분포는 이산확률분포 → "정규분포, 이항분포"는 연속확률분포 연결이 아님 |
| 26 | ② | 유사도 기반 그룹화는 **군집분석** |
| 27 | ① | "DB 설계가 쉽다"는 분산 DB의 장점이 아님 |
| 28 | ② | 계층구조는 블록, 파일, **디렉토리** (데이터 아님) |
| 29 | ③ | "계층구조를 구성한다"는 DBMS가 아닌 파일시스템의 개념 |
| 30 | ① | 데이터에 대한 데이터는 **메타데이터** |
| 31 | ② | 테이블의 열, 고유 이름, 데이터 유형 정의는 **속성(Attribute)** |
| 32 | ③ | 3단계 구조에 "내용 스키마"는 없음 |
| 33 | ① | 레코드를 고유 식별하는 키는 **기본키(Primary Key)** |
| 34 | ① | 데이터 병합 명령어는 **INNER JOIN** |
| 35 | ③ | 데이터 접근 제어는 "역할에 따라 **데이터 사용 권한 할당**" |
| 36 | ① | 웹 스크래핑은 "웹사이트에서 **데이터를 추출**하는 과정" |
| 37 | ④ | NoSQL은 "유연한 스키마, **비정형/반정형 데이터 처리**" |
| 38 | ① | 데이터 무결성 검증은 "**정확성, 완전성, 일관성** 보장" |
| 39 | ① | BI 활용 목적이 아닌 것은 "데이터 보안 강화" |
| 40 | ③ | BI 구현 이점은 "**의사결정 능력 및 전략적 통찰 향상**" |

### 제3과목: 경영정보시각화 디자인 (41-60번)

| 번호 | 정답 | 해설 |
|------|------|------|
| 41 | ① | "균형"의 설명이 "비례"의 설명과 혼동됨 |
| 42 | ③ | 반복 패턴 형성은 **리듬** |
| 43 | ② | 간결하고 이해하기 쉽게 만드는 원칙은 **오컴의 면도날** |
| 44 | ① | "비교 및 대조 인포그래픽" 설명으로 적절하지 않음 |
| 45 | ② | 색상/패턴/기호를 설명하는 요소는 **범례** |
| 46 | ② | 셀 내 작은 차트는 **스파크라인** |
| 47 | ④ | Power BI는 데이터 추출/변환 기능도 제공 — 틀린 설명 |
| 48 | ① | 대시보드는 상호작용/필터링 기능을 **제공함** |
| 49 | ④ | 시간 전후 관계 표현에 적합한 것은 **경사차트** |
| 50 | ④ | 해당 차트는 **덴드로그램** |
| 51 | ③ | 불확실성 표현에 적합한 것은 **수평오차막대** |
| 52 | ③ | 해당 차트는 **생키차트** |
| 53 | ② | 버블차트의 장점이 아닌 것: 범주형 비교에 적합하다는 설명 |
| 54 | ① | 스파이더차트: "비교 항목이 네 개 이상일 경우에만 사용"은 틀림 |
| 55 | ① | 범주형에 "위치"는 분류/구분보다 정량 비교에 더 적합 |
| 56 | ④ | 박스플롯: "신뢰구간 표시"는 주요 특징이 아님 |

| 58 | ③ | 면적 왜곡 지도는 **카토그램** |
| 59 | ② | 해당 차트는 **분위수-분위수 차트(QQ도표)** |
| 60 | ④ | Priestley 역사차트가 아닌 **간트차트**와 유사 — 정답 수정: ② 간트차트 |
